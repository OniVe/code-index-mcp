# code-index-copy

Копия проекта вместе с готовым индексом code-index. Индекс копии не строится заново:
в копию переносится база индекса исходника, и демон копии при запуске только сверяет
файлы с базой (время изменения и размер) — разбирать ему нечего.

Нужна, когда с проектом работают в отдельной копии: исполнитель на внешней модели,
несколько параллельных правок, проверка на чистом дереве. Без неё индекс каждой
копии строится с нуля — для выгрузки 1С это минуты.

## Что делает

1. **Проверки.** Исходник — корень рабочего дерева git (подкаталог — отказ).
   Приёмник и каталог индекса копии не существуют или пусты.
2. **Копия файлов** — одним из двух способов:
   - по умолчанию — файлы под контролем git (`git ls-files`) копируются с сохранением
     времени изменения; содержимое — как на диске исходника, включая незафиксированные
     правки отслеживаемых файлов; файлы, которых нет на диске (например, LFS вне рабочего
     дерева), пропускаются и считаются в отчёте;
   - `--worktree --branch <ветка> [--commit <коммит>]` — `git worktree add` на новой
     ветке (по умолчанию от HEAD), хуки проекта не исполняются, концы строк — как у
     исходника. Затем файлам копии, совпадающим с исходником по размеру и не правленым
     относительно коммита, ставится время изменения исходника; строки файлов, правленых в
     исходнике относительно коммита, удаляются из базы копии — демон проиндексирует их заново.
3. **Перенос базы** `<исходник>/.code-index/index.db` в `<приёмник>/.code-index/index.db`
   через SQLite backup API — базу может держать работающий демон. Нет базы у исходника —
   не ошибка: копия без базы, индекс построится с нуля (пометка в отчёте).
4. **Очистка базы копии** от файлов, которых в копии нет (файлы исходника вне git):
   средствами ядра code-index, с затиранием освобождаемых ячеек (`secure_delete`), затем
   сжатие таблиц полнотекстового поиска.
5. **Конфиги индекса копии** (если задан `--index-home`): `daemon.toml` со строкой
   `[[cache_targets]]` на сервер выдачи копии и `serve.toml`. Без этой строки демон не
   сообщает серверу выдачи о переиндексации, и сервер до часа отдаёт из кэша прежний ответ.
   Демон и сервер выдачи программа не запускает — это дело вызывающего.

## Ключи

```
code-index-copy <ИСХОДНИК> <ПРИЁМНИК>
    [--worktree --branch <ВЕТКА> [--commit <КОММИТ>]]
    [--index-home <КАТАЛОГ> --port <ПОРТ> --alias <АЛИАС> [--language <ЯЗЫК>]]
```

| Ключ | Что задаёт |
|---|---|
| `--worktree` | копия через `git worktree` вместо копирования файлов; требует `--branch` |
| `--branch` | имя новой ветки копии |
| `--commit` | коммит, от которого создаётся ветка (по умолчанию HEAD) |
| `--index-home` | каталог конфигов индекса копии — будущий `CODE_INDEX_HOME` её демона и сервера выдачи |
| `--port` | порт сервера выдачи копии |
| `--alias` | алиас репозитория копии в её индексе |
| `--language` | язык индекса копии (как в `daemon.toml`) |

Пример — копия с веткой и конфигами индекса, затем запуск демона и сервера выдачи копии:

```
code-index-copy C:/Repo1C C:/Temp/work/task1 --worktree --branch agent/task1 \
    --index-home C:/Temp/work/_indexes/task1 --port 8123 --alias work --language bsl
set CODE_INDEX_HOME=C:/Temp/work/_indexes/task1
bsl-indexer daemon run
bsl-indexer serve --transport http --host 127.0.0.1 --port 8123 ^
    --config C:/Temp/work/_indexes/task1/daemon.toml --serve-config C:/Temp/work/_indexes/task1/serve.toml
```

## Отчёт и коды выхода

В stdout — одна строка JSON: `ok`, способ (`mode`), ветка и коммит, счётчики файлов
(`files_copied`, `files_skipped`, `mtime_aligned`, `not_aligned_size`, `not_aligned_modified`,
`not_aligned_missing`), `db_transferred` и `db_note`, `db_paths_removed` (убрано файлов, которых в
копии нет), `db_paths_stale` (убрано файлов, правленых в исходнике: их индексирует демон копии),
время каждого шага в
`timings_ms`. Сообщения о ходе работы — в stderr.

| Код | Значение |
|---|---|
| 0 | копия готова (в том числе без базы, если её нет у исходника) |
| 2 | ошибка в ключах |
| 3 | исходник не корень рабочего дерева git |
| 4 | приёмник или каталог индекса копии не пуст |
| 5 | сбой копирования файлов или записи конфигов |
| 6 | сбой подготовки базы (перенос, выравнивание времени, очистка) |

При сбое в отчёте — `error.stage` (шаг) и `error.message` (текст ошибки дословно, та же
строка в stderr), и всё, что создал этот запуск, откатывается: файлы копии, база, каталог
индекса копии, ветка (только `git branch -d`; если git откажет — причина в `rollback`).

## Сборка

```
cargo build --release -p code-index-copy
```

Готовые архивы для Windows, Linux и macOS — в выпусках репозитория.
